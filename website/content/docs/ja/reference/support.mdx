### 現在の主な制約

- 標準HTTP APIはPostgreSQL、WebSocket、HTTP/2、ストリーミング、サーバー側TLSを提供しません。
- Actorは同一プロセスのTokioタスクです。BEAMプロセスと同じ障害隔離を保証しません。
- `elif`と関数の名前付き引数は未リリースです。公開0.2.3向けソースでは使いません。

## 開発中の Go ターゲット

以下は 0.3.0 に向けた未公開の実装状況です。公開 Nagi 0.2.3 には含まれません。

| 機能 | 開発状況 |
|---|---|
| ネイティブビルドと基本機能 | `--backend go` で明示選択。基本型、関数、class、`Option`、`Result`、`try`、所有権の一部に対応。 |
| async | ユーザー定義 async の直接 `await`、`sleep` など限定範囲に対応。公開 `Task`、`scope`、`spawn` は未対応。 |
| HTTP (M21) | IPv4 ループバックでの直接 `serve`、完全一致の公開 `GET` / `POST` ルート、本文なしの GET、固定長 POST のバイナリ往復と本文上限を確認。 |
| HTTP の状態 (M39) | スカラー・文字列で構成した読み取り専用の共有 State を、`await` を含まない名前付き handler で確認。共有可変 State や中断・再開する handler は対象外。 |
| CORS | `cors_policy` と `cors_route` で明示設定したルートの許可 Origin と `OPTIONS` プリフライトを確認。未設定ルートは CORS ヘッダーを追加しない。 |
| 整数変換 | `i32(i64)` は範囲を検査し、範囲外は `Error` を返す。既存の損失のない `i64` 拡張も利用可能。 |
| エラーの確認 | `error_kind` は Go が対応するエラーの分類を、エラーを消費せずに取得する。メッセージは `error_message` で取得できる。 |
| 整数の読み取り | `parse_i64` は文字列と読み取り専用文字列ビューに対応する。10進数の範囲、エラー分類、メッセージは Rust backend と同じ。 |
| JSON | 単独の `json_encode` は `str`、`bool`、整数に対応。浮動小数点・集約型の符号化、`json_decode`、HTTP の JSON 応答は未対応。 |
| 標準ライブラリの未対応機能 | 公開 Actor / Supervisor、SQLite Pool/Tx、認証、Session、CSRF は未対応。 |
| ネイティブアダプター | Go ネイティブアダプターは未対応。Go ターゲットでは Rust 資産を拒否。 |

HTTP の確認は Linux 上で、High・生成して保存した Low・手書き Low を通常の CLI に通して行いました。Go 配布 smoke の `--go-smoke` は、外部 Go toolchain を使用する明示オプションです。これらの結果は Linux の開発検証に限ります。他 OS と正式配布の検証は別途必要です。
