# A quote API combining Axum and Nagi

[日本語](README.md)

Build the HTTP layer in Rust with Axum, and write types, business validation, and calculation in Nagi. This example uses existing Rust integration rather than Nagi's standard HTTP server.

```sh
nagic run --project test-nagi-code/application-examples/axum-service
```

Run from the repository root. This example is verified with Nagi 0.1.10. nagic and Rust/Cargo are required. The server listens at `http://127.0.0.1:8097`; change the port with `NAGI_SAMPLE_PORT`. Press Ctrl+C to stop.

```sh
curl http://127.0.0.1:8097/health
curl -H 'Content-Type: application/json' -d '{"quantity":2}' \
  http://127.0.0.1:8097/quotes
```

The quote is `{"quantity":2,"total_minor":2500}`. Each item costs 1250 minor currency units. Quantity must be between 1 and 100; validating that range before calculation keeps this multiplication within the integer range.

| Owner | Implementation |
| --- | --- |
| Nagi: [main.nagi](main.nagi) | Input and quote classes, a custom error enum, quantity validation, an async calculation function |
| Rust: [native.rs](native.rs) | Axum routes and JSON extraction, HTTP status mapping, a loopback listener, shutdown, an async timer |
| Cargo: [nagi.toml](nagi.toml) | Axum and Tokio dependencies |

For `POST /quotes`, Axum decodes JSON into `QuoteInput` and the Rust handler calls `super::calculate(input).await`. Nagi's `calculate` awaits Rust's `pause`, then returns `Result[Quote, QuoteError]`. Rust maps success to 200 and business rejection to 422. JSON conversion uses the Serde implementations generated by Nagi.

The adapter directly references a known generated Nagi async function by name. It does not pass an arbitrary async callback value through a Nagi extern parameter. `check` validates Nagi types and ownership; `build` validates the Rust calls and future requirements. Update the adapter when changing those function names or types. `map` does not analyze Rust routes or this Rust-side call.

Out-of-range quantities return JSON with `invalid_quantity`. Axum rejects malformed JSON with 400, missing/extra fields and wrong types with 422, and a missing Content-Type with 415. Extractor error bodies use Axum's format.

This adapter configures a 4096-byte JSON body limit and graceful shutdown on Ctrl+C. Nagi's standard HTTP connection limits, receive/handler/send deadlines, panic-to-500 conversion, and shutdown deadline do not apply automatically. Authentication, TLS, databases, and panic recovery are not included. Cancelling an async wait does not guarantee rollback of external work or state changes. `pause` is a timer demonstrating the async round trip, not a database operation.

For a POST missing Content-Type, the adapter reads the body up to 4096 bytes, with a one-second deadline from the start of that read, before returning 415. Size limits, read errors, and deadline expiry keep 415 priority; an incomplete read requests connection close. Unread data or a disconnected client can still prevent delivery of the response. This wait applies only to the missing-header rejection, not valid JSON or an existing invalid Content-Type. Tokio's timeout is cooperative and does not forcibly interrupt CPU-bound work. Rejected requests add buffering and waiting; unchanged cost is not guaranteed.

`smoke.py` checks successful quotes, quantity boundaries, rejected JSON, recovery after invalid input, invalid port settings, and listener release over real HTTP. See the [sample catalogue](../README.md) for the shared runner. Linux and macOS verification checks graceful Ctrl+C exit; Windows verification terminates the process from the test.

The shared runner also executes native unit tests from each successful High and saved-Low build generation. Real HTTP checks cover split body writes and rejection of 4097-byte JSON; controlled futures cover the deadline, read errors, and cancellation/drop. These cases do not cover every TCP partition or keep-alive reuse.
