Ownership and cleanup limits:
- TaskScope owns only its monitor/HTTP JoinSet records, not actor workers or HTTP connections. It awaits actual native joins of its direct children.
- actor::run owns Supervisor, requests group stop, releases factories/context lease, and elects the drainer. Successful run completion waits terminal native records and context cleanup. Context cleanup uses Arc::try_unwrap at runtime/src/actor/lifecycle.rs:124; a retained external Context Arc delays completion.
- Canceling/dropping actor::run releases its drainer lease and Supervisor owner and requests stop. A separate retained Control + actor::shutdown can elect the remaining drainer. Successful shutdown Ok proves actor/context terminal completion. A Context Drop signal alone proves destruction, not native joins/terminal publication. Shutdown Err alone is ambiguous between completed retained failure and incomplete timeout; use known scenario cause and independent completion barriers, or design cancellation-only cases to require Ok.
- Establish actor.ready/start barriers before parent Drop/panic/HTTP error if testing running cleanup. Otherwise unpolled run takes a different unstarted path and shutdown can reject as not run.
- serve_listener owns its connection JoinSet. Explicit graceful shutdown drops listener, signals connections, awaits their drain and on deadline aborts then drains. Canceling the server future synchronously drops its JoinSet, requesting nested connection abort; parent TaskScope joining that server does not universally await arbitrary nested handler Drop/close completion. Docs should keep this distinction. If pending handler cleanup is observed, report its independent barrier/event separately from server-native join.
- Do not infer forced stop of non-yielding work, safe arbitrary blocking Drop, rollback, resource close success, exactly-once effects, or automatic context-cycle recovery.
