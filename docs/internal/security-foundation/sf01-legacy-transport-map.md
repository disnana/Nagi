# SF01 legacy HTTP transport/test migration map

SF01 uses one policy-required `http_server` resource path. The legacy private Axum `Router` adapter and its separate `serve` lifecycle are removed; they are not retained as a fallback. The accepted decisions are recorded in [D1–D3](decisions-and-migration.md), especially the single dispatcher and explicit removal of built-in health, streaming, and WebSocket routes.

## Legacy HTTP tests

| Removed test in `runtime/src/http/tests.rs` | Current coverage or adopted removal | Preserved intent and limit |
|---|---|---|
| `request_wait_configuration_is_positive_finite_and_defaults_to_ten_seconds` | `options_validate_capacity_deadlines_and_leave_state_out_of_debug`; `header_idle_deadline_is_independent_of_send_deadline_after_flush` | Positive explicit deadlines and header timeout validation remain. The `NAGI_HTTP_REQUEST_WAIT_SECONDS` environment override and the separate legacy server default are removed; callers configure `Options` directly. |
| `silent_partial_and_dripped_headers_expire_without_extending_the_deadline` | `header_deadline_expires_silent_dripped_and_buffered_partial_requests` | Real sockets cover a silent connection and a partial header whose bytes arrive in intervals. The absolute header deadline must expire despite the drips. |
| `idle_reuse_and_buffered_partial_requests_share_the_header_deadline` | `header_idle_deadline_is_independent_of_send_deadline_after_flush`; `header_deadline_expires_silent_dripped_and_buffered_partial_requests` | Reused keep-alive connections, two successful buffered requests, and a buffered incomplete next request retain the header deadline. The send deadline remains independent. |
| `streaming_and_backpressure_can_outlast_the_request_wait` | `stalled_response_send_expires_and_releases_connection_permit`; `graceful_shutdown_preserves_stalled_response_send_deadline`; finite body tests | Backpressure and send-deadline cleanup remain covered. The new response API returns one finite buffered `Bytes` representation; the old long-running chunked response-stream success behavior is intentionally removed. These tests do not promise general streaming support. |
| `websocket_upgrade_is_exempt_from_the_http_wait` | No replacement by design; see `successful_connect_is_rejected_instead_of_establishing_an_unowned_tunnel` for the related unsupported tunnel boundary | Automatic `/ws` and protocol upgrade support are removed. No unauthenticated upgrade path is restored or promised. A trusted host that needs WebSockets requires a separately reviewed lifecycle and authorization boundary. |
| `body_timeout_remains_separate_from_header_wait` | `actual_chunk_sizes_and_absolute_body_deadlines_are_bounded`; `oversized_body_declared_length_rejects_headers_and_incomplete_upload_promptly`; `oversized_body_boundary_accepts_4096_and_incomplete_upload_keeps_body_deadline` | Body and header budgets remain separate and are exercised over real sockets with small request bodies and incomplete uploads. |
| `healthy_requests_work_with_more_than_128_idle_connections_and_shutdown_closes_them` | `connection_capacity_supports_more_than_128_idle_sockets_and_shutdown_closes_them`; `connection_capacity_and_shutdown_deadline_leave_no_handler_tasks` | 129 idle sockets coexist with a normal small request under an explicit connection limit above 128, and shutdown closes the idle sockets. This verifies that configured capacity and shutdown behavior, not unlimited admission, remain available. |

`/health`, `/stream`, and `/ws` were injected by the old `http_router` helper. They are absent from the new API. The `/healthy` handlers used in panic and shutdown tests are explicit test routes; they do not restore an implicit health endpoint. An application that needs health reporting must register its own route and choose a policy. The old stream sample is not a capability promise for arbitrary response streams.

## Legacy panic test

`runtime/src/http/panic_tests.rs::handler_extractor_and_response_panics_return_sanitized_500_for_get_and_head` covered panic during handler construction, handler polling, an extractor, `IntoResponse` conversion, and arithmetic/index failures. The new direct `(Request, Arc<S>, A) -> Result<Response, E>` boundary covers the supported panic points in `runtime/src/http_server/panic_tests.rs`: constructor panic, panic after `await`, mapper panic, division by zero, and out-of-bounds access. Those checks preserve sanitized 500 responses, connection close, a subsequent explicit healthy route, and HEAD body suppression with its representation length.

Axum extractor and `IntoResponse` extension hooks no longer belong to the public handler path, so their old adapter-specific panic fixtures are intentionally removed. The server still catches panics from supported native handler and mapper callbacks; this does not roll back application state or promise preemption of non-yielding Rust code.
