# SF05: literal Query and SQLite admission contract

2026-10-09. Implementation contract based on SF00 D1–D3 and SF01. SF02 Sessions remain unimplemented; 0.2.0 is unreleased. [日本語](sf05-contract.md).

The canonical module is `stdlib:std.db.sqlite`. `literal(sql: str) -> Query` accepts a direct string literal. The checker rejects variables, views, concatenation, formatting and function results at the constructor argument's original source position with `SF05 literal Query`. It recognizes canonical operation identity, preserving unrelated user functions with the same name. Query is opaque, Copy and shareable, and has no public fields, JSON reconstruction or dynamic factory. Parameters retain their existing non-Copy value-binding contract.

`query[T](tx: view[Tx], query: Query, parameters: Parameters)`, `all[T]` and `exec` require Query. Legacy string arguments receive a specific `SF05 migration` diagnostic. Query values can be stored, passed, returned and selected from reviewed fixed alternatives. Direct-literal enforcement belongs to the constructor; Rust static lifetime restrictions do not become additional public Nagi syntax. The checker does not implement a second SQL parser. A sealed constructor plan stores the literal payload and drives emission. Regular check does not require the SQL engine.

Legacy builtin Db and db_open/db_exec/db_all/db_query/db_insert/db_update/db_write, plus public runtime Db/Sql and dynamic factories, are removed. Checker-only migration tombstones remain. User functions/classes are distinguished by canonical identity. No deprecated execution path or compatibility flag remains. FromRow and column indices remain because the current SQLite decoder uses them.

Pool/Tx/Options/Parameters/Failure/Outcome, native authorizer, single-statement prepare, binding/value/NULL checks, row shape, zero-millisecond acquisition, cancellation, rollback, cleanup and actual close retain their existing contracts. A literal does not prove SQL intent or tenant authorization. Reviewed trusted host management handles schema/bootstrap without reexporting a request-facing dynamic factory. The existing authorizer allow/deny policy is preserved.

Trusted application startup in the examples performs fixed reviewed DDL/seed operations from main before registering HTTP routes. This management code is separate from request handlers; it exposes no request-facing SQL-string factory. Native fixtures may instead seed through a trusted Rust host. This separation does not add a new authorizer policy that bans all DDL.

Protected operations use a reviewed trusted adapter that binds the Grant's actual subject and target into owner/tenant predicates. Generic queries do not gain a Grant argument that claims to prove those predicates. A Rust-host-only opaque queue reservation awaits bounded capacity; reservation is not admission. The adapter passes it to Grant.submit, binds the supplied subject/target in the callback, and synchronously enqueues once through that reservation. Only the already-enqueued reply is awaited. Reservation and Query are not authorization proofs; adapter and predicate correctness remain trusted.

A small native fixture in one SQLite file demonstrates correct subject/target updates, unaffected data for another tenant/target, revocation before permit issuance with zero enqueues, and the reverse order as one admitted enqueue. As in SF01, local admission linearizes at single-use permit issuance under the gate. Invalidation after issuance, including before the callback synchronously enqueues, leaves the operation already admitted. The oracle also distinguishes invalidation after enqueue but before the SQL step. It also tests revocation during finite capacity waiting and one-time permit consumption. Cancellation after admission does not prove rollback. DB session/permission changes require predicates or revalidation in the same transaction. This work does not claim SF02 session-generation guarantees.

Validation separates contract, minimal RED and implementation; High, independently saved Low after deleting High, handwritten Low, aliases/replacements, native business parity and source-position rejection. Parse/import/API absence, unrelated restrictions, panic, zero filters and skips do not establish the intended negative oracle. Raw logs, snapshots, source SHA-256, cache/toolchain/command/exit provenance, independent review, regression/fmt/clippy/fuzz/examples, bilingual documentation and four-OS CI are recorded. Merge, version, tag and release require separate authorization.
